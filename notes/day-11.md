# Day 11：重构共享网关并构建 V2.5 菜单候选

日期：2026-11-16

## 目标与整合边界

- 以用户已在 SameBoy 验收的 V2.4.5 作为运行回归基线，将主命令菜单一级列表加入 V2.5。
- 为保持构建可重现，V2.5 仍从不可变 V1 重建 V2.4.5 功能，再叠加菜单；补丁目标是 V1，而不是 V2.4.5。
- 菜单新增译文为「状态、法术、道具、重要物品、装备」，伴随信息框为「盘缠」。
- 初步对照发现菜单试点与对话功能争用共享入口和扩展 bank，不能直接叠加。采用重构共享网关的方案：菜单使用 `$00A0` 入口，文本主网关改到 `$00E0`；bank10 路由器按调用返回地址区分菜单关闭、对话恢复和普通文本路径。菜单字形由 ROM 保存并恢复，不借用 `$C000–$CFFF` 作运行时备份区。

## 机器码问题与回归保护

- 静态核对生成的 bank10 路由器时发现，三个 `JR NZ` 的分支修补位置指向了操作码本身，导致生成器会覆盖跳转指令。此缺陷版没有交给用户进行 SameBoy 测试。
- 修正分支占位字节的生成方式，并新增精确路由器机器码测试，覆盖菜单关闭、对话恢复及普通路径的分支编码。

## 构建与自动化验证

- V2.5 ROM：1 MiB，SHA-256 `0e83086a639f8bab536a0e82ce67f52ca166e37d3a48bb51f8babe6d80b5c8f4`。
- V1→V2.5 BPS：13,414 字节，SHA-256 `f8d5511bea03cab5a0008c4aa776c00147b2ecd8a3b76bd252693353beb904ff`。
- 3 项定向测试和 144 项全量测试通过；Python 语法检查、ROM checksum 和 BPS 往返验证通过。连续两次构建的 ROM 与 BPS 哈希一致。
- 构建输入、输出哈希及验收范围记录在 [V2.5 版本清单](../versions/V2.5-main-menu.json)。

## SameBoy 运行结果与待定位项

用户已确认 SameBoy 加载的是上述 SHA-256 的 V2.5 ROM，并报告游戏进入**无限重启**。因此该候选的运行验证状态更新为失败，不得标记为通过；V2.4.5 仍是当前已验收运行基线。

用户提供的快照为 `AF=$B700, BC=$12B5, DE=$00D1, HL=$CD4B, SP=$FFFC, PC=$04F8, IME=Enabled`，backtrace 为 `$20:$04F8 ← $20:$0170`。V2.5 与 V2.4.5 在 `$0170` 和 `$04F8` 附近的 ROM 字节完全相同。`$0170` 是 `CALL $04F7`，调用前设置 `HL=$C000, BC=$2000, A=0`；`$04F7` 起是清零 `[HL]` 并递减 `BC` 的循环。当前 `HL=$CD4B` 与剩余 `BC=$12B5` 正好吻合已清零 `$0D4B` 字节的进度。故这份快照是进入启动例程后正在清 WRAM，不是触发重启的位置，也暂不能说明为什么再次进入启动。

随后提供的入口快照为 `AF=$0080, BC=$2000, DE=$03D1, HL=$C000, SP=$FFFE, PC=$0170, IME=Enabled`，backtrace 只有 `$20:$0170`。这正是 `$0170` 执行 `CALL $04F7` 前的初始状态，确认 CPU 又进入启动初始化；它仍没有记录重启前的来源。

随后在 `$20:$1803` 的主文本入口捕获到 `AF=$3B70, BC=$0000, DE=$0100, HL=$D366, SP=$DFF3, IME=Enabled`，backtrace 为 `$20:$1803 ← $20:$194B ← $20:$1935 ← $21:$76D2`。快照中 `$FFAA=$04`、`$FFAD=$1D`、`$FFAE=$33`，`$C4F0–$C4F2=00 00 00`。这与已确认的开场文本入口签名 `$04/$33/$1D` 完全吻合，标记也表示缓存尚未加载；因此该停点是开场文本的第一次候选分派，不是命名画面的非目标 fallback，也还没有捕获到崩溃指令。应继续确认其是否经过 `$00E0`、bank10 router/dispatcher、开场 loader `$4B00`、返回 handler `$0061` 并到达 `$180C`。

### 与此前开场前故障对照

- V2 在主角命名画面停于 `$00A0EC`。已确认旧构建把从 `$00E0` 开始的 32 字节 postlude 写到 `$00FF`，覆盖了 `$00F7–$00FF` 的 V1 非目标 fallback。V2.5 的 fixed gateway 实际长度为 21 字节，覆盖 `$00E0–$00F4`；ROM 中 `$00F7–$00FF` fallback 保持原样，因此没有复现这项已知覆盖错误。
- V2.1 在开场文字前停于 `$24:$4083`。其已确认根因是 bank `$30` gateway 在 `$4007` 恢复 bank `$04` 后，还继续从 `$400A` 的 banked window 取指。V2.5 的 `$00E0` 固定区代码在 `$00EE` 写回原 bank，随后仍在固定区执行 `$00F1` 并跳到 `$0061`；静态字节布局没有复现“恢复 bank 后继续从 banked window 执行”的旧序列。
- 五上下文候选也曾在开场即死机，但当时没有可归因的寄存器/backtrace 根因，不能用它证明 V2.5 是同一故障。

### 另一个已发现但不能解释开场前重启的问题

V2.5 菜单关闭钩子位于 ROM 文件偏移 `$8946`；替换后的 `CALL $00E0` 返回文件偏移 `$894A`。该位置属于 banked ROM window，映射到 Game Boy CPU 地址 `$494A`，而原 bank10 router 错误比较 `$894A`（低字节 `$4A`、高字节 `$89`）。这会使菜单关闭恢复分支无法命中，可能造成随后对话的字形/图块异常。后续已修正为比较 CPU 返回地址 `$494A`，并更新精确 router 机器码测试。

### 启动文字未匹配路径对照

V2.4.5 在 `$00A0` 先检查文本指针高字节；非目标指针会直接进入 `$00F7` fallback。V2.5 将 `$1803` 改为跳到 `$00E0`，因此普通文本调用也会先进入固定 gateway 和 bank10 dispatcher。dispatcher 检查 `$C4F2`、`$FFAA`、`$FFAE/$FFAD`；未匹配的 banked 分派会调用 `$4E00`，其无匹配尾路径为 `XOR A; RET`。状态 `A=0` 回到固定 `$0061` handler 后，再进入 `$00F7` fallback。此路径多了一次 bank 切换和分派，与已验收 V2.4.5 的早期 pointer gate 不同；它是值得运行时核对的差异，但当前没有 `$1803` 停点寄存器证明它就是重启原因。

目前快照确认启动初始化再次运行，并已捕获到开场入口 `$20:$1803` 的正确签名。

### Fixed gateway 错误恢复 bank 的修正

后续 SameBoy 快照在 `$24:$76D5` 停住，回溯对应调用点 `$21:$76D2`；`x $FFA8` 显示 `$FFA9=$01`、`$FFAA=$04`。bank shadow 位于 `$FFA9`，而首个 V2.5 gateway 在 `$00EE` 从 `$FFAA` 读取恢复值，因而把当前 ROM bank 错误恢复为 `$04`，调用返回后便从 bank `$24` 的数据区取指。现已将 V2.5 gateway 的读取操作数改为 `$FFA9`；V2.4.5 基线签名仍按原样检查，不作修改。

修正版 ROM SHA-256 为 `fdd9996e5c257f27c949f24bd9eec9a533ad0e517f61b84fe2c6033d91d1057d`，BPS SHA-256 为 `c7882d24751be886de26ce14e0d0ac4e9bce9549c0751e734c8188ec9e30efbf`。4 项 V2.5 定向测试通过；构建器完成 ROM checksum 和 BPS 往返检查。此修正版尚待 SameBoy 运行回归，V2.4.5 仍是当前已验收基线。

### SameBoy 回归后的菜单关闭路由修正

用户确认 bank 恢复修正版可显示开场文本和自由活动一级菜单，但通知板、女人、伽罗对话译文仍乱码。根据上面的已知地址映射问题，router 已从比较文件偏移高字节 `$89` 改为比较 CPU 地址高字节 `$49`；这样从 `$4946` 调用 gateway 返回 `$494A` 时才能进入菜单图形恢复 helper。

最新候选 ROM SHA-256 为 `0910626205c6cb0678529e588162e08973fecabd9a2032bb90a7b15b8432499e`，BPS SHA-256 为 `52460cfdc8fe8c2fac3f48a3aaf019b2aee0daa4a325e6409a09edd6c2fba108`。4 项 V2.5 定向测试通过，构建器完成 ROM checksum 与 BPS 往返校验；该候选的 SameBoy 菜单关闭及对话回归仍待确认。
